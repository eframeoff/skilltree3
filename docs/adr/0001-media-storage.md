# ADR 0001 — Хранение и загрузка медиа (видео / фото / файлы)

- **Статус:** принято
- **Дата:** 2026-06-16
- **Контекст плана:** [docs/ROADMAP.md](../ROADMAP.md), Фаза 7

## Контекст

Ученики загружают попытки и зачёты в узлы дерева (видео / фото / текст / файлы),
тренер их проверяет и оценивает. Сейчас медиа — мок (`VideoPlayerPlaceholder`,
`thumb` = цвет), реального хранилища нет — поле чистое.

Рассматривалась идея **не хранить видео у себя**, а класть их в соцсети ученика
(TikTok, Instagram) через привязанный аккаунт: экономия на хранилище + бесплатная
реклама, если клип наберёт лайки.

## Решение

**Разделяем два слоя, которые нельзя смешивать.**

### Слой 1. Хранилище сдач — наше, всегда (обязательное, приватное)

Ядро LMS строим на собственном object storage, а не на соцсетях:

- **Видео:** Cloudflare Stream / Mux / Bunny (транскод, адаптивный стрим,
  превью из коробки, дёшево за минуту).
- **Фото / файлы:** Cloudflare R2 (нулевая плата за egress — главный пожиратель
  бюджета на медиа).
- **Загрузка:** прямая по presigned-URL из браузера в хранилище, мимо
  app-сервера.
- **Просмотр:** подписанные (signed) ссылки для тренера / наставника.
- **Ретеншн ярусами:** одобренные зачёты и featured-клипы — долгое хранение
  (диплом + материал подборки); отклонённые черновики авто-удаляются через N дней.
- Клиентское сжатие перед загрузкой.

### Слой 2. Соцсети — маркетинг поверх (опционально, opt-in)

- Ученик привязывает аккаунт (TikTok / Instagram / YouTube).
- «Поделиться» доступно только для **одобренных** клипов из подборки
  (`is_featured` / `compilation_ready` уже есть в модели).
- Публичные метрики (лайки) привязанного клипа читаем best-effort → лидерборд /
  подборка. Зависит от публичности и API — не критический путь.

### Влияние на модель (`parts[]` из Фазы 0)

`submit.kinds` получает `link`/`embed`; попытка хранит части двух видов:

```js
{ kind:'video', payload:{ storageKey, playbackUrl, thumb, duration } } // хостим мы
{ kind:'embed', payload:{ provider:'tiktok|instagram|youtube', url, thumb } } // хостит соцсеть
```

- Внешняя ссылка = ноль хранения у нас + соц-пруф; тренер смотрит во встроенном
  плеере.
- **Высокие ставки (зачёт-гексагон) требуют хостимую копию** — её нельзя удалить
  задним числом. Практики можно принимать по `embed`. Per-node политика в духе
  `delegation` / `grade`.

## Почему не «соцсети как хранилище»

- **Контроль не наш.** Ученик удалит / закроет клип, его снимут по жалобе →
  доказательство сдачи исчезает, целостность диплома ломается. Тренер обязан
  видеть именно ту попытку, которую оценивал.
- **Privacy и несовершеннолетние.** Тренировочные видео детей (футбол, музыка)
  нельзя по умолчанию выкладывать в открытый доступ — safeguarding + GDPR.
  Кривой дубль ученик показывать миру не хочет.
- **Хрупкость API.** Жёсткий app-review, ограниченные scope, rate-limits, смена
  ToS, deprecation встраивания. Отдавать ядро продукта внешней платформе нельзя.
- **Экономия иллюзорна.** Копия для проверки нужна всё равно; почти весь денежный
  выигрыш даёт легально R2 с бесплатным egress.

## Последствия

- Нужен бюджет на видео-хостинг — снижается ярусным ретеншном и egress-free R2.
- Привязка соцаккаунтов и app-review — отдельная работа Слоя 2, не блокирует ядро.
- Клиентам с публичными постами даём embed — экономия хранения там, где безопасно.

## Альтернативы (отклонены)

- **Соцсети как источник истины** — ломает проверку, приватность, надёжность.
- **Только self-host без шеринга** — теряем бесплатный виральный канал.
- **YouTube unlisted как бэкенд** — те же риски удаления / смены политики,
  плюс не закрывает фото и файлы.
